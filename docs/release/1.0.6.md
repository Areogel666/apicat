# ApiCat 1.0.6 Release Notes

**发布日期**：2026-09-24
**版本类型**：Stable Maintenance & Polish Release

---

## 关于此版本

ApiCat 1.0.6 是一次**稳定性收口 + 启动体验打磨**的版本。上一版（1.0.5）把 HTTP Bridge、AI 技能、断言引擎推上线后，本版集中处理正式包在真实用户机器上暴露的技能安装链路问题，并把「第一次打开 App」的引导闭环补齐。

主线三件事：

1. **AI 技能安装链路彻底修通**——正式包找不到 `skills/` 目录（Tauri 打包把 `../skills/` 的父级 `..` 重命名为 `_up_`）、Windows 卸载 junction 报「拒绝访问」、Linux AppImage 软链随 App 退出悬空、复制式安装的技能副本永远拿不到更新——四个环环相扣的问题一并修掉，且打包侧改用 `resources` map 形式消除 `_up_` 歧义（治本）。
2. **启动序列梳理**——补齐「首次启动自动引导装技能」（1.0.5 文档承诺但代码缺失）、新增「启动时静默检查更新」（同版本只提示一次），并修掉两者并行触发导致的双模态叠加、以及启动序列里「记住上次打开项目」被静默吞掉的问题。
3. **响应区与布局细节打磨**——响应体落文件阈值 100KB → 1MB、大响应完整落文件（`MAX_BODY_SIZE` 2MB → 32MB）、JSON 树深层节点可点击展开、全展开/全收起按钮、左侧栏收起后留门把手式折叠引导。

## 重点功能说明

### 🧩 AI 技能安装链路（本版核心）

1.0.5 发布后正式包上「安装技能」报「未找到内置技能目录（skills/）」，根因是 Tauri bundler 把 `bundle.resources` 里 `"../skills/"` 的父级 `..` 重命名为 `_up_` 目录 → 实际安装树是 `{InstallDir}/_up_/skills/...`，而 `builtin_skills_dir()` 只查了 `resource_dir()/skills`。三平台同现（同一 `tauri.conf.json` + 同一 `builtin_skills_dir`）。

**修复策略**（治本 + 兼容双管齐下）：

- **治本**：`resources` 改 map 形式 `{"../skills/": "skills/"}`，显式指定目标路径后不再触发 `_up_` 重命名——新包技能直落 `resources/skills/`。
- **兼容**：`builtin_skills_dir` 生产分支改双候选探测 `resource_dir()/_up_/skills`（旧包命中）+ `resource_dir()/skills`（新包命中）。
- **Windows 卸载**：junction 在 Rust `symlink_metadata` 下 `is_dir()` 返回 **false**（旧注释是错的），被误判为普通文件走 `remove_file` → `ERROR_ACCESS_DENIED`。改三段式 `remove_dir` → `remove_file` → `remove_dir_all`，顺序不可调换。
- **Linux AppImage**：`create_link` 检测到 `APPDIR` 环境变量时跳过软链、直接文件复制（软链目标在 `/tmp/.mount_XXXX/` 挂载点内，App 退出即悬空）。
- **复制式安装刷新**：副本加 `.apicat-skills-version` 出厂版本标记，启动时比对不一致就删除重刷；链接式安装不比对（`read_link()` 可区分，实测 junction 与 symlink 均返回 Ok）。
- **`repair_skill_links` 死代码修复**：原 `if !dest.exists() { continue; }` 守卫会跟随链接看目标，悬空链接的 `exists()` 恰好为 false 直接 continue，「悬空重建」分支永远不执行——1.0.5 宣称的「App 更新后自动修复悬空链接」**实际从未生效**。守卫改 `symlink_metadata()`（看链接本身），悬空判定保留 `!exists()`（看目标）。

### 🚀 启动序列

- **首启技能引导**：判定口径「`anyAgentAvailable && !anySkillInstalled`」——**技能完全没装过**（所有目标都没有任何 apicat 技能）且有 agent 目录可用时才弹，避免「只装了 Claude Code 的人被反复提示 Codex」。标记从布尔改为记 App 版本（`startup.skillGuideShownVersion`）。
- **启动检查更新**：`getVersion()` 对比 `app-settings.json` 上次提示版本，同版跳过；`check()` 失败静默不打扰。手动入口保持完整反馈。
- **双弹窗串行**：引导先、更新后；更新检查弹框前若引导开着则让位且不写标记。
- **「记住上次打开项目」**：启动序列（theme → projects → restoreLastProject → bridge）整体暂停持久化，避免启动期写入覆盖上次项目 id。

### 📦 响应体分层

| 大小 | 行为 |
|------|------|
| `≤ 1MB` | 内联渲染（JSON 树 / 高亮） |
| `1MB – 32MB` | 完整落文件，DB 存 `@file:{history_id}`，前端可「另存为」 |
| `> 32MB` | 截断并置 `is_truncated=1`（安全兜底） |

旧约定（100KB 落文件 / 2MB 截断）会让普通列表响应被迫走「另存为」、且 10MB 响应存进文件的也只有前 2MB——**超出部分永久丢失**。本版阈值调整后 1MB–32MB 的响应完整落文件，`@file:` 前缀语义与 DB 标记格式不变，前端零改动。

### 🎨 布局与响应树

- **折叠把手**：折叠态在内容区左缘留门把手式窄把手，`mouseenter` 临时展开当前栏作预览（不持久化），`click` 才真正切换 `collapsed` 并持久化；`activity-toggle` 折叠按钮兜底常显。
- **JSON 树展开修复**：`JsonTree.vue` 原 `expanded = depth < deepInit && !collapsedPaths.has(path)` 对深于默认层级的节点**恒为 false**，用户 `toggle()` 后渲染不变化——表现为「点击无反应，Ctrl+F 后才能点」（Ctrl+F 把 `expandLevel` 置 999 后 `depth < 999` 恒真）。改为显式状态优先、默认深度兜底。
- **全展开/全收起**：响应工具栏新增切换按钮。

## 重要修复

- **正式包安装技能报「未找到内置技能目录」**（P0，三平台）——`_up_` 前缀路径错位 + 打包侧 map 形式治本
- **Windows 卸载技能报「拒绝访问 (os error 5)」**（P0）——junction 元数据误判，改三段式删除
- **Linux AppImage 技能软链悬空**（P1）——App 退出即失效，改文件复制
- **`repair_skill_links` 悬空重建是死代码**（P1）——1.0.5 宣称的自动修复从未生效
- **技能副本无刷新机制**（P1）——复制式安装的用户拿不到技能更新
- **首启技能引导未实现**（P1）——1.0.5 文档承诺但代码缺失
- **启动「检查更新」与「技能引导」双弹窗叠加**（P1）——改串行 + 让位
- **「记住上次打开项目」失效**（P1）——启动序列整体暂停持久化
- **启动白屏**（P1）——`useDialog`/`useMessage` 必须在 provider 子树内调用
- **响应体落文件阈值过小**（P1）——100KB → 1MB；顺带修 `MAX_BODY_SIZE` 2MB 截断在落文件之前导致的响应丢失
- **JSON 树深层节点点击无法展开**（P1）——显式切换与默认深度解耦
- **文档页左侧栏缺分界线与底色**——与接口树/字典树对齐

**遗留待实机验证**（本版未收口）：

- **[P0] Linux 用例管理页悬停白屏**——疑似 WebKitGTK 渲染进程崩溃，需 Linux 实机稳定复现 + 控制台日志再定修法（`TestCaseManager.vue` 嵌套 `overflow` 容器在 WebKitGTK 下 hover 重绘是白屏高发结构）
- 打包 map 形式是否让 msi `Directory` 表彻底无 `_up_`（新包技能是否落在 `resources/skills`）——发版后验证

## 工程与维护改进

- **打包配置**：`tauri.conf.json` `resources` 数组改 map 形式（`{"../skills/": "skills/"}`），先用数组包对象的写法不满足 schema（commit `1ff4b06` 修正为直接对象）
- **技能安装器**：`create_link` / `remove_link` / `repair_skill_links` / `builtin_skills_dir` 四个函数的 Windows / Unix / AppImage 三分支逻辑统一收敛；副本与链接用 `read_link()` 区分
- **启动状态收编**：新增 `src/stores/startupChecks.ts` 统一管「首启引导已提示版本」+「上次检查更新版本」
- **主题 token 化**：折叠把手、文档页左侧栏等样式改用 CSS 变量而非硬编码 px，跟随 `density`/`fontSize` 档位

---

## 兼容与升级

- 无 migration 变更，老库直接升级；
- 旧包（含 `_up_/skills`）由双候选探测兼容，升级到 1.0.6 后新包走 `resources/skills` 干净路径；
- 复制式安装的技能副本会在下次启动时按版本标记自动重刷为 1.0.6 内容，无需手动重装；
- 链接式安装（Windows junction / macOS symlink）自动跟随 App 资源目录，升级即最新；
- 建议升级：**所有 1.0.5 用户**——尤其 Windows（卸载修复）、Linux AppImage（技能自包含）、以及任何用 AI 技能驱动 ApiCat 数据的场景。
