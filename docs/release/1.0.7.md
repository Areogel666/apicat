# ApiCat 1.0.7 Release Notes

**发布日期**：待定
**版本类型**：Feature Release — Cookie 全链路 + AI 技能版本自检

---

## 关于此版本

1.0.6 是稳定性收口，1.0.7 回头补一块一直残缺的能力：**Cookie**。

此前 Cookie 模块只做了一半——能建、能看、能删，但**发不出去**：用户在 Cookie 管理里填好 cookie，实际请求不带；复制为 cURL，命令里没有；跑用例、压测，同样没有。另一边，从浏览器复制的 cURL 带着 `-b` 导进来，cookie 内容**静默丢失**，不报错也不提示。

这一版把 Cookie 的整条链路补齐：存 → 导入 → 注入 → 回存 → 导出，并顺手修掉这条链路上几个会让功能整体不可用的硬伤。

另附一项独立改进：**AI 技能版本自检**。技能随 App 打包分发，此前装完就看不见状态，现在技能管理能显示是否落后于当前版本并一键更新。

---

## 核心更新

- **Cookie 三级作用域**：全局 / 项目 / **环境**（新增），覆盖优先级 `环境 > 项目 > 全局`
- **`Set-Cookie` 自动回存**：响应里的 cookie 自动进 Cookie 管理，下次请求自动带上
- **四条链路统一注入**：调试 Send、跑用例、压测、导出 cURL 全部带上 cookie
- **curl 导入补 Cookie**：`-b/--cookie` 与 `-H 'Cookie: ...'` 归一，另补 `-u` / `-A` / `-e`
- **domain 匹配放宽到子域**：父域 cookie 能命中子域请求，`Domain=.example.com` 不再失效
- **Secure 语义生效**：标 Secure 的 cookie 只在 https / wss 请求中发送（此前只存不判）
- **Cookie 可视化编辑**：管理弹窗直接改已有 cookie（含过期时间），不必删了重建
- **重复 Cookie 拦截**：同组键重复添加时明确提示，不再静默堆积
- **AI 技能版本自检**：技能管理显示是否落后于当前 App 版本，一键更新

## 重点功能说明

### 🍪 Cookie 作用域与匹配规则

`cookies` 表新增 `env_id` 列，作用域由两级变三级：

| 作用域 | project_id | env_id | 典型用途 |
|---|---|---|---|
| `global` | 空 | 空 | 所有项目共用 |
| `project` | 非空 | 空 | 某项目下所有环境共用 |
| `env` | 非空 | 非空 | 测试 / 生产各自的登录态 |

同名（name + path）cookie 取**最高层**那条。匹配规则：

- **domain 子域匹配**：`host == domain` 或 `host` 以 `.` + `domain` 结尾。存 `intl.miui.com` 能命中 `ias-app.cms.intl.miui.com`
- **path 前缀匹配**：`/api` 命中 `/api/user`
- **`expires_at` 参与过滤**：过期的不发
- **`secure` 参与过滤**：标 Secure 的 cookie 只在 https / wss 请求中发送（本版起生效，此前是「只存不判」）
- **`http_only` 只存储展示**：它约束的是浏览器页面脚本能否读 cookie，而 ApiCat 不是浏览器、没有可执行该约束的对象；保留字段只为忠实还原导入的 cookie
- **`Max-Age` 优先于 `Expires`**；两者都没有 = 会话 cookie，落库但**永不过期**，需手动清理

> **迁移说明**：首次启动会重建 `cookies` 表以加 `env_id`（SQLite 无法 ALTER 唯一约束）。同时清掉历史遗留的孤儿行（`scope_type='project'` 但 `project_id` 为空的记录，这些记录此前哪儿都查不到）。

### 📥 Set-Cookie 自动回存

请求拿到响应后，`Set-Cookie` 会被解析并写进 Cookie 管理，下次请求自动带上——不再需要手动抄 token。

- 回存层级：有项目 + 环境 → `env` 层；只有项目 → `project` 层；都没有 → `global` 层
- 同名（domain + path + name + 作用域）覆盖
- **设置菜单可关**：「⚙️ 自动保存 Set-Cookie」，默认开
- 需要 `expires_at` / `http_only` / `secure` 写入能力的旧记录：这三个字段此前是**只能读不能写**的死字段，本版补齐

### 🔗 四条链路统一注入

此前只有「调试 Send」一条路会注入 cookie，其余三条各自绕过：

| 链路 | 本版行为 |
|---|---|
| 调试 Send | 按 URL host 命中 cookie 存储，与手动 `Cookie` 行合并成一条 |
| 跑用例 | 同上（此前完全不注入） |
| 压测 | **启动时一次性注入**，并快照进 `stress_runs.config_json.cookie_snapshot`（与 P95/P99 阈值快照同一套「报告可复现」模式）。引擎不做逐请求注入 |
| 导出 cURL | 用 `-b` 带上命中 cookie，与手动 `Cookie` 行同序合并 |

合并顺序固定为 **`手动; 存储`**，不会产生两个 `Cookie` 头。

### 📋 curl 导入补齐

`-b/--cookie` 此前**完全未解析、静默丢弃**——这就是「导入了带 `-b` 的接口但 cookie 没写进来」的原因。本版：

- `-b/--cookie` 与 `-H 'Cookie: ...'` **语义等价**，统一归一成接口 header 的一条 `Cookie` 行
- 归一后弹一次「要把这些 Cookie 存进 Cookie 管理吗？」，默认作用域 = 当前项目 + 当前激活环境
- `-u/--user` → `Authorization: Basic ...`
- `-A/--user-agent` → `User-Agent`
- `-e/--referer` → `Referer`
- `-L / -k / --compressed` **不再静默吞**，导入完显式提示「以下参数已忽略」（`-k` 会注明 App 默认已忽略证书校验）
- `-b` 接 cookie jar **文件路径**（不含 `=`）时不当成 cookie 串写入，改为显式提示

### ✏️ Cookie 可视化编辑

此前改一条 cookie 只能删了重建。现在行尾 `✎` 直接编辑：域名 / 名称 / 值 / 路径 / 过期时间 / HttpOnly / Secure 全可改。

- **作用域锁定不可改**（后端约定）：换作用域只能删了重建，避免唯一键冲突
- 一并补上**过期时间输入**（新建与编辑都有）——后端 `expires_at` 本已支持，此前 UI 没有入口。清空 = 会话 cookie
- 时间按 UTC 存取、按本地时区展示：落库是 `YYYY-MM-DD HH:MM:SS` 无时区标记，需显式按 UTC 解析（`new Date(s)` 对这类串的时区行为跨引擎不一致，会整体偏移数小时）
- **弹窗内分区**：列表与编辑区用分隔线 + 标题切开，新建入口移到顶部工具条，正在编辑的行高亮，列表长时自动滚到编辑区（此前点 ✎ 像是「没反应」）

### 🚫 重复 Cookie 拦截

添加一条与已有 cookie 同组的（作用域 + domain + path + name）时明确提示「已存在同名 Cookie（…），请编辑已有条目」，而不是静默新增。

根因是**表上的唯一约束形同虚设**：`UNIQUE(scope_type, project_id, env_id, domain, path, name)` 中，global 层的 `project_id` / `env_id`、project 层的 `env_id` 都是 NULL，而 **SQLite 的 UNIQUE 索引遇 NULL 列不判等**——实测 global / project 层可无限插入完全相同的行，只有 env 层被真正拦住。故改为应用层查重（`IS ?` 让 NULL 参与比对）。

- **Set-Cookie 回存不受影响**：它走独立的 `upsert_cookie`，命中即覆盖，本就是正确的
- 存量重复行**本版不清理**（需要的话手动删）

### 🔍 AI 技能版本自检

技能随 App 打包分发（`tauri.conf.json` 的 `resources` 带 `skills/`），故**技能版本 ≡ App 版本**，没有独立版本号。技能管理弹窗现在显示每个目标的状态与版本，落后时给出「更新」按钮。

判定三种「不是当前 App 那一份」的情况：

| 情况 | 判据 |
|---|---|
| 链接悬空（App 换了安装路径） | 链接本身在，目标不在 |
| **链接指向旧版 App 残留目录** | 链接目标 ≠ 当前 App 的内置技能目录 |
| 副本版本标记过期 | `.apicat-skills-version` ≠ 当前 App 版本 |

第二种是本次补上的漏判：旧逻辑只看「链接有没有悬空」，而旧 App 还在磁盘上时链接并不悬空，于是状态一直显示正常、技能内容却是旧的。链接判据改为比对目标路径——两侧 `canonicalize` 后比较，兼顾 Windows junction 的 `\\?\` 前缀与大小写不敏感（直接比字符串会把**所有**有效链接误判成过期）。

- App 启动仍**静默自动修复**（行为不变，只是判得更准）
- 「更新」按钮复用安装逻辑，**未新增后端命令**

## 重要修复

- **填了 cookie 但请求不带**：domain 填完整 URL（如 `https://api.example.com/path`）时，与 URL host 做「字符串精确相等」匹配永不命中。现改为规范化（剥 scheme / userinfo / path / query / port / 开头的点）后再匹配，新建表单输入框也会即时规范化
- **项目级 cookie「没跟项目绑定」**：Cookie 管理把项目列表加载挂在 `n-tab-pane` 的 `@click` 上，而点 tab 标题不冒泡到 pane，导致**切过去永远不重载**、看到的是上一个项目的数据。现改为打开弹窗即加载，UI 也从「分 tab」改成「一张表 + 作用域筛选」
- **孤儿 cookie 行**：没有激活项目时仍可保存项目级 cookie，落成 `project_id=NULL`，之后列表和发送都查不到。现加保存校验，并在迁移中清掉存量
- **Bridge 侧项目 cookie 永不注入**：`projectId` 不传就绑 NULL。现改为**由后端按 `requestId` 反查 `api_requests → collections → projects` 自推**——project_id 是接口的固有属性，不该由调用方指定。Bridge 的 `projectId` 字段保留兼容但**不再采信**
- **`expires_at` / `http_only` / `secure` 三列是死字段**：任何写入路径（Tauri command 与 Bridge）都写不进去，只能读。现已补齐 `create_cookie` / `update_cookie` 的写入

## 工程与维护改进

- 抽出 `src-tauri/src/cookies.rs` 作为 cookie 语义层**唯一真源**（domain/path 匹配、`Set-Cookie` 解析、注入合并、回存 upsert）。`get_cookies_for_domain` 与各发送链路统一走 `collect_cookies_for_url`，不再各自内联 SQL
- `parseCurl` 从 `Sidebar.vue` 抽成 `src/utils/curlParser.ts` 纯函数，并补**零依赖自检**：`npm run check:curl`（Node 22+ 的 `--experimental-strip-types`，不引入测试框架）
- 抽 `cookies::find_cookie_id` 作 cookie 查重**唯一真源**（`IS ?` 比对，NULL 也参与）：Set-Cookie 回存与手工新建共用，附回归测试锁住「不能用 `=`」
- 抽 `skill_installer::skill_state` 作技能版本判定**唯一真源**：UI 展示与启动静默修复共用，杜绝「UI 说过期、启动认为没事」的两套标准
- Bridge 补注册 `GET /get_cookies_for_domain`（此前只有 Tauri command，技能侧调不到）
- Bridge `update_cookie` 的 `enabled` 同时接受布尔与整数 0/1（此前传布尔静默无效）
- Bridge `list_cookies` 缺 `project_id` 时改走 NULL 语义（此前绑 `0`，永远查不到项目行）
- 5 份 AI 技能文档对齐新契约：`apicat-lib` 的 `bridge-api.md` / `SKILL.md` / `apicat_schema.md`、`apicat-edit`（新增 Cookie CRUD 章节 + Markdown 导入的 cookie 落成 header 行）、`apicat-test-gen`（用例与压测的 cookie 语义）、`apicat-doc-gen`（接口文档记录 Cookie，取值脱敏）

## 兼容与升级

- **数据库**：首次启动自动迁移 `cookies` 表（加 `env_id` + 调整唯一约束 + 清孤儿行），无需手动操作
- **HTTP Bridge 契约**（`apicat-lib` 技能依赖）：
  - `POST /send_request` 的 `projectId` **保留但被忽略**，老脚本无需改动，行为只会更准
  - 新增可选字段 `persistSetCookies`（或 `persist_set_cookies`，默认 `true`）
  - `POST /create_cookie` / `POST /update_cookie` 新增可写字段，均为可选，不传不受影响
  - **⚠️ `POST /create_cookie` 行为变更**：同组键重复时返回错误（此前 global / project 层会静默插入重复行）。要改已有条目请改走 `POST /update_cookie`
  - **⚠️ Secure 行为变更**：标了 `Secure` 的 cookie 在 `http://` 请求上不再发送。测内网 http 接口时若发现 cookie 没带上，检查该 cookie 的 Secure 勾选
  - `send_request` 响应新增 `cookie_skipped`（因 Secure 被跳过的条数），向后兼容
  - 新增 `GET /get_cookies_for_domain`
- **IPC**：`send_request` 新增可选参数 `persistSetCookies`；`list_cookies` / `create_cookie` / `update_cookie` / `get_cookies_for_domain` 新增可选参数，不传即旧行为
- **IPC**：`get_skill_targets` 返回值新增 `skills` / `bundled_version`（原 `installed_skills` 被 `skills` 取代）——仅影响自研调用方
