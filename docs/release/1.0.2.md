# ApiCat 1.0.2 Release Notes

**发布日期**：2026-05-15
**版本类型**：Stable Feature Release

---

## 关于此版本

ApiCat 1.0.2 在 `v1.0.1` 多标签页工作流的基础上，补齐了响应展示、用户偏好和用例管理三大块短板。

如果你经常需要查看多种格式的响应（XML / HTML / Markdown / YAML）、希望应用记住你的工作偏好、或者用例多到管理不过来——1.0.2 会带来明显的体验跃升。

同时，本版本铺设了 CSS Token 主题底座，正式支持 **Light / Dark / 跟随系统** 三种主题切换，是后续主题定制能力的基础。

---

## 核心更新

| 功能 | 说明 |
|------|------|
| 响应多格式渲染 | 自动识别并渲染 JSON / XML / HTML / YAML / Markdown / Text，每种格式提供 Raw / Pretty / Preview 视图模式 |
| 响应全文搜索 | 鼠标悬停响应区按 `Ctrl+F` 自动展开 JSON 树，再次按 `Ctrl+F` 由浏览器原生搜索接管 |
| 启动恢复项目 | 应用重启自动恢复到上次打开的项目，多项目场景免手动切换 |
| 主题底座 | 内置 Light / Dark / 跟随系统三套主题，TopBar 设置菜单一键切换，自动持久化偏好 |
| 用例独立管理 Tab | 与 Params/Headers/Body/Auth 平级的"用例"Tab，左右分栏（列表 + 历史详情） |
| 用例历史调用记录 | 每个用例自动记录最近 10 次调用（状态码、耗时、响应摘要），SQLite 触发器自动滚动淘汰 |
| 批量删除用例 | 多选 + 二次确认，一键清理无用用例 |

## 重点功能说明

### 📦 响应多格式渲染

之前版本只对 JSON 做了优化展示，其他格式都按原始文本展示。1.0.2 引入完整的格式渲染体系：

- **自动识别**：按 `Content-Type` + 内容嗅探，自动选择最合适的渲染器
- **手动覆盖**：响应面板顶部新增格式选择器和视图模式切换，用户可强制按指定格式渲染
- **5 种渲染器**：
  - JSON：基于 `vue-json-pretty` 的折叠树（默认展开 3 层）
  - XML / HTML 源码：`highlight.js` 语法高亮
  - HTML 预览：最严沙箱 `<iframe sandbox="">` + `referrerpolicy="no-referrer"`
  - YAML：`js-yaml` 解析 + 高亮
  - Markdown 预览：`markdown-it` 渲染 + DOMPurify 双重过滤防注入
- **视图状态隔离**：格式覆盖、视图模式按 `requestId` 内存级分桶，切换接口互不干扰

### 🔍 响应全文搜索（Ctrl+F）

JSON 折叠树有个老问题：响应内容被收起后浏览器原生搜索找不到。1.0.2 解决方案：

- 鼠标悬停响应区按 `Ctrl+F` → 全展开所有节点 + Toast 提示
- 第二次按 `Ctrl+F` → 浏览器原生搜索接管
- 大响应体（>500KB）自动 fallback 到 Raw 模式，避免全展开卡顿
- 不影响其他输入框的 `Ctrl+F` 行为

### 🎨 主题底座（Light / Dark / 系统跟随）

CSS Token 体系正式落地：

- 设计 token 分 4 类：中性色 / 品牌色 / 语义色（含 HTTP 方法、状态码桶）/ 形态变量
- 通过 `<html data-theme>` 切换 CSS 变量，全应用瞬时响应
- TopBar 设置菜单新增"主题"二级菜单，三选一切换
- 用户偏好持久化到 `app-settings.json`，重启保留
- "跟随系统"模式下实时监听 `prefers-color-scheme`

### 💾 启动恢复项目

之前每次启动都打开"第一个项目"。1.0.2：

- 切换项目时自动持久化最近打开的项目 ID
- 启动时校验项目仍存在 → 自动恢复
- 项目被删除时优雅降级到默认行为，不会报错

### 📋 用例独立 Tab 管理

之前用例只能从顶部横条切换，没有集中视图。1.0.2 在右侧 NTabs 中新增"用例"Tab：

- **左右分栏**：左列用例列表（默认 35%），右列历史详情（默认 65%）
- **列表能力**：
  - 多选 + 批量删除（NPopconfirm 二次确认）
  - 双击行内重命名 / 右键菜单（重命名 / 切换收藏 / 删除）
  - 按名称或更新时间排序（默认更新时间倒序）
- **历史详情**：
  - 点击列表某行 → 右栏懒加载该用例最近 10 次调用记录
  - 状态徽章按桶着色（2xx 绿 / 3xx 蓝 / 4xx 黄 / 5xx 红 / 网络失败灰）
  - 一键复制响应摘要

### 🗃️ 用例执行历史（DB 层）

新建 `test_case_history` 表 + SQLite 触发器 `trg_tch_keep_10`：

- 每次激活用例并发送请求，自动写入历史（状态码、耗时、响应摘要 ≤1KB）
- 触发器自动保留每用例最新 10 条，超出按时间倒序淘汰
- 用例删除时通过外键 CASCADE 自动清理关联历史

## 重要修复

### 🔧 稳定性修复

- 修复完整 URL + 无激活环境时报 `relative URL without a base` 的发送失败问题
- 修复 NDataTable 在 flex-height 模式下用例列表显示空白的问题（tbody 滚动容器高度算成 0）
- 修复用例管理面板 Dark 主题下背景仍为白色但文字为白色看不清的问题（NaiveUI 局部 CSS 变量在自定义 div 上拿不到，全量替换为 :root 全局 token）

### 🛡️ 工程稳定性

- 加固 SQLite migration 解析器使用规范（避免注释中分号字面量被误拆，详见 1.0.3 计划）
- 触发器创建逻辑独立到 `db/mod.rs`，绕开 split-by-semicolon 解析器对 BEGIN/END 复合块的支持限制

---

## 工程与维护改进

- **CSS Token 全量化**：替换 118 处 NaiveUI 内部变量引用为全局 token，主题切换不再有"NaiveUI 跟随但自定义组件不跟随"的不一致问题
- **持久化抽象层**：新增 `_persistedSettings.ts` 统一封装 `@tauri-apps/plugin-store`，所有用户偏好共享 `app-settings.json`，便于 1.0.3 主题编辑器、布局密度等扩展
- **主题 store 与 NaiveUI 联动**：`themeStore.naiveOverrides` computed 从 CSS 变量动态读取主色，确保 NConfigProvider 与全局 token 同步切换
- **代码评审 commit 体系**：1.0.2 改动按 M2 / M3-A / M3-B / M3-C 拆 8 个 commit，便于 bisect 定位问题

## 升级建议

- 如果你当前在 `v1.0.1`，建议升级到 `v1.0.2` 以获得多格式响应渲染和主题切换能力
- 频繁查看 XML / HTML / Markdown 响应、有 Dark 模式偏好、有大量用例需要管理的场景，此版本收益最明显
- 数据库自动升级：新增 `test_case_history` 表是幂等创建，老用户无需手动迁移，启动即生效
