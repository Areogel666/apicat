# ApiCat 1.0.5 Release Notes

**发布日期**：2026-09-19
**版本类型**：Stable Feature Release

---

## 关于此版本

ApiCat 1.0.5 的核心是 **Localhost HTTP Bridge + AI 断言引擎 + 技能安装器**，把 ApiCat 从「桌面调试工具」扩展为「可被 AI 技能直接驱动的本地数据服务」，并补齐了压测报告的真源下沉与接口文档面板。

Bridge 在本地 17320 端口起一个 REST 服务（启动生成随机 token 写入 `bridge.json`），所有技能（apicat-lib / apicat-test-gen / apicat-doc-gen）经 Bridge 读写接口、字典、用例、压测 —— 数据真源收敛到一处，技能脚本不再直连 SQLite。断言模块让测试用例可声明「期望状态码 / JSON Path 校验」，发送后给出通过/失败判定。技能安装器一键把技能装进各 Agent 的 skills 目录，App 更新后自动修复悬空的 junction 链接。

配套：压测报告 Markdown 生成器下沉到 Rust（App 与技能共用同一真源），报告预览弹窗支持渲染与 md/html 导出；侧边栏新增「接口文档」面板。

## 重点功能说明

### 🔌 HTTP Bridge

- 监听 `127.0.0.1`，端口 17320 起、占用顺延；token 写入 `~/.apicat/bridge.json`，技能通过 `Authorization: Bearer <token>` 访问；
- 协议：REST，前缀 `/api/v1/`，路径与 IPC command 名对齐；GET=只读（query 参数），POST=写（JSON body）；
- 写操作后广播 `bridge-data-changed` 事件，前端各 store 自行 reload —— 技能改完数据，桌面 UI 即时反映；
- Bridge 开关存 `app-settings.json`（默认开启），无需重装依赖。

### 🤖 AI 技能体系

- 技能脚本收拢到 `skills/` 三件套：`apicat-lib`（库访问底座 + 桥接客户端）、`apicat-test-gen`（用例生成/压测）、`apicat-doc-gen`（接口文档生成）；
- 技能安装器在 App 内一键安装/卸载，junction 用 `mklink /J`（免管理员权限）；
- App 更新（资源目录被替换）后，启动时自动扫描修复悬空技能链接。

### ✅ 断言模块

- 用例可附加断言：`{"type":"status_code","operator":"eq","expected":"200"}` 与 `{"type":"json_path","path":"$.code","operator":"eq","expected":"0"}`；
- 断言求值引擎在 Rust 侧（`assertion` 模块），发送请求后对响应做校验并给出判定；断言编辑交互完善。

## 重要修复

- 4 项阻塞/高优问题修复（code review 后）：技能触发、相对 URL 处理、断言日志、断言 UX
- 中文 body 必须走 heredoc/文件传输 —— 内联会被 Git Bash 转码（技能脚本）
- 接口查重改为 method + url，避免从文档导入出重复项
- junction 路径分隔符混用（正斜杠）导致 mklink 失败的隐患
- 文档「打开所在目录」打开 C 盘、用例压测 `{{base_url}}` 未替换
- 字典项目隔离、复制字典 UNIQUE 约束等 4 个问题

## 工程与维护改进

- **types 镜像漂移对齐**：`types.rs ⇄ types/index.ts` 两处字段对齐
- **P-series 后端清理**：列清单常量统一到 `sql_cols`、bridge 双键取值收敛为 `get_str/get_i64`、写操作抽 `_impl` 收敛 bridge 与 commands 业务分叉、消除 N+1 IPC 与历史列表全量拉 body
- **前端去冗余**：拖拽排序逻辑抽为 `useCollectionTreeDnd` composition；清死代码
- **回归脚本修正**：`repro-draft-pollution.mjs` 按 1.0.4 真实 bug（防抖落库 id 漂移）重写，闭环成立（旧 50/50 污染、新 0/50）
- **CI**：macOS 打包补 `app` bundle，修复 `latest.json` 缺失 `darwin-*` 条目（Mac 收不到更新的问题）；记录发布流程四个坑

## 兼容与升级

- Migration 幂等，老库无需清空；Bridge/断言均为新增能力，不影响既有接口、用例、字典数据；
- 技能目录经原生资源打包，升级后 skills/ 由 App 自动维护，无需手动重建链接；
- 建议升级：需要在别的工具/AI 助手驱动 ApiCat 数据、或要更严谨的用例断言与报告时，收益最直接。
