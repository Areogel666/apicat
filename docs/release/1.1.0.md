# ApiCat 1.1.0 Release Notes

**发布日期**：2026-11-16
**版本类型**：Feature + Stability Release — 项目级 Headers 模板 + 更新弹窗重构 + Bridge 能力补齐 + Linux 渲染探测

---

## 关于此版本

1.1.0 主要围绕四件事：

- **项目级 Headers 模板**——公共 Headers 模板从全局 localStorage 改为按项目落库，切换项目互不干扰，旧数据自动迁移
- **更新体验**——更新提示从纯文本 `dialog.info` 改为 Markdown 弹窗，长 release notes 在弹窗内滚动，不再撑出屏幕
- **Bridge 能力补齐**——补齐 1.0.9+ 审计发现的遗漏端点，AI 技能可直接批量排序/移动目录与接口、批量删除/隐藏用例
- **Linux 渲染探测**——默认渲染档改为按 GPU 探测（i915 → software，其他 → auto），`software` 档真正禁用 GPU，并消除 AppImage 的 at-spi 协议报错

---

## 核心更新

- **公共 Headers 模板按项目落库**：新增 `header_templates` 表（`project_id` 外键级联删除），启动迁移自动建表；新增 `list_header_templates` / `save_header_templates` IPC；前端 store 从 localStorage 改为 DB 读写，随项目切换加载/落盘
- **旧模板自动迁移**：升级用户首次加载到某个项目时，旧版 localStorage 的全局模板会迁入该项目（只迁一次）并删除旧 key
- **更新提示 Markdown 弹窗**：新增 `UpdateDialog`，复用 MarkdownRenderer 渲染 release notes，内容区 `max-height 45vh` 内部滚动、标题与按钮固定；启动检查与 ⚙️ 手动检查共用同一弹窗
- **Bridge 端点补齐**：新增 7 个数据端点——用例批量删除 `delete_test_cases`、批量隐藏 `set_test_cases_hidden`；目录排序 `update_collection_sort`、移动 `move_collection`；接口排序 `update_request_sort`、移动 `move_request`；字典跨项目复制 `copy_dictionary_to_project`
- **写操作单一实现**：上述端点把原先写在 IPC 层的业务逻辑抽成 `*_impl`，IPC 与 Bridge 共用同一份实现，符合「写操作真源」约定
- **Linux 渲染探测**：首次启动探测 GPU——Intel i915 → `software`，AMD/NVIDIA → `auto`，结果写回配置；`software` 档在禁用 DMABUF/合成之外追加 `LIBGL_ALWAYS_SOFTWARE=1`，确保 WebKitWebProcess 不再打开 `/dev/dri/renderD128`
- **消除 at-spi 报错**：启动时设置 `NO_AT_BRIDGE=1`，修复 AppImage 内 libatspi（22.04）与系统 at-spi2-core 协议不匹配导致的 `unknown signature` 刷屏
- **主题修复**：玻璃质感档位按钮补 `white-space:nowrap`，主题工作室宽度不足时整组折行，不再把「更透/标准/更实」挤成两行
- **主题导出/导入完善**：导出改用系统保存对话框并显示完整路径；导出/导入补全玻璃质感四项（`glass` / `glassBlurEnabled` / `glassBlur` / `glassAlpha`）与 `mode`，旧版 v1.0 文件仍可导入（缺字段保持当前值）

## 重点功能说明

### 📋 项目级 Headers 模板

- 每个项目独立维护一份公共 Headers 模板，切换项目自动加载对应模板
- 编辑期是内存态 + 400ms 防抖整份提交；后端事务内全删全插，不会出现「删了没插」的半套模板
- 切换项目前先 flush 旧项目，避免防抖窗口内的编辑写到新项目头上
- 升级用户：旧版全局模板只迁入首个加载到的项目；其他项目如需相同模板，请在模板弹窗中手动添加

### 🔔 更新提示

- Release notes 现以 Markdown 渲染，支持标题/列表/代码块；长日志在弹窗内滚动，不再撑出屏幕
- 「安装更新」的下载进度、失败提示与重启确认统一收敛到弹窗，不再散落多个 `dialog` / `message`

### 🔌 Bridge 能力补齐

- AI 技能现在可以批量整理目录与接口结构（排序、移动）、批量删除/隐藏用例
- 所有新增写端点统一 camelCase / snake_case 双键取值，写操作后广播 `bridge-data-changed`，桌面端自动刷新
- 移动目录含循环引用防护（不能移进自己的子孙）
- 字典跨项目复制必须换新 `code`（全局唯一）：可传 `newCode` 指定，缺省自动生成 `{源码}_copy`（冲突递增 `_copy2`…）；字典项与源项目字段规则一并复制，目标项目已有同字段名则跳过

### 🐧 Linux 渲染

- 默认档位不再固定 `shm`：i915 用户首启自动进入 `software`；AMD/NVIDIA 用户保持 `auto`
- 探测结果写回 `app-settings.json`，UI 显示与实际一致；用户手动选择优先
- `software` 档同时设置 `WEBKIT_DISABLE_DMABUF_RENDERER`、`WEBKIT_DISABLE_COMPOSITING_MODE` 与 `LIBGL_ALWAYS_SOFTWARE`，避免仅关闭前两者时仍向 i915 提交命令
- 若曾在 `.desktop` 的 `Exec` 中写入 `env WEBKIT_DISABLE_DMABUF_RENDERER=1`，请移除，否则外部变量会覆盖 UI 渲染档设置

## 升级注意

- **版本号**：1.1.0（package.json / package-lock.json / tauri.conf.json / Cargo.toml / Cargo.lock 已同步）
- **Headers 模板迁移**：旧全局模板只迁入首个打开的项目；如需在其他项目使用，请在模板弹窗中手动补充
- **Linux 渲染档**：升级后首启会按 GPU 探测写回配置；i915 默认 `software`（CPU 渲染，界面可能略慢，但可避开 GPU HANG）
- **自动更新**：Linux 仅 AppImage 支持应用内自动更新；deb 需手动安装。更新包必须由 CI 用匹配私钥签名，`latest.json` 必须发布（不能是草稿）
