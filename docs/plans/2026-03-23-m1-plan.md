# M1: 项目脚手架 + DB 初始化 + 基础布局 实现计划

> **状态：✅ 已完成**  
> **完成日期：2026-03-23**

**Goal:** 初始化 Tauri 2.x + Vue 3 + SQLite 项目，建好 DB 迁移脚本（8 张表），跑通三栏布局。

**Architecture:**
- Tauri 2.x 作为桌面容器，Rust 后端通过 `sqlx` 直连 SQLite，前端 Vue 3 + Naive UI 渲染三栏布局。
- DB 初始化在 Tauri `setup` 阶段同步完成（`block_on`），migration SQL 编译时内嵌进二进制（`include_str!`）。
- 前端通过 Pinia store 管理全局状态（darkMode、sidebarWidth）。

**Tech Stack:** Tauri 2.x, Rust/sqlx 0.8/tokio, Vue 3/TypeScript/Vite, Naive UI, Pinia

## Task 3: SQLite Migration SQL

**已完成文件：**
- `src-tauri/migrations/0001_init.sql`

**包含 8 张表：**
1. `projects` — 项目
2. `environments` — 环境（dev/test/prod）
3. `env_variables` — 环境变量
4. `collections` — 接口分组（支持无限嵌套，parent_id 自引用）
5. `api_requests` — 接口定义（params/headers/body 存为 JSON 文本）
6. `request_history` — 调试历史（含 `is_truncated` 字段，超 2MB 截断标记）
7. `cookies` — Cookie（全局+项目级，含 UNIQUE 约束防重复积累）
8. `test_cases` — 测试用例（含 `starred` 收藏字段、断言 JSON）

**7 条外键索引：**
```sql
CREATE INDEX IF NOT EXISTS idx_env_proj    ON environments(project_id);
CREATE INDEX IF NOT EXISTS idx_coll_proj   ON collections(project_id);
CREATE INDEX IF NOT EXISTS idx_coll_parent ON collections(parent_id);
CREATE INDEX IF NOT EXISTS idx_req_coll    ON api_requests(collection_id);
CREATE INDEX IF NOT EXISTS idx_hist_req    ON request_history(request_id);
CREATE INDEX IF NOT EXISTS idx_tc_req      ON test_cases(request_id);
CREATE INDEX IF NOT EXISTS idx_tc_coll     ON test_cases(collection_id);
```

**设计要点：**
- `cookies` 表含 `UNIQUE(scope_type, project_id, domain, path, name)` 防重（Eng Review 10.5）
- `request_history` 含 `is_truncated INTEGER DEFAULT 0`（响应超 2MB 截断，Eng Review 10.5）
- 所有 SQL 使用 `CREATE TABLE IF NOT EXISTS` / `CREATE INDEX IF NOT EXISTS`（幂等）

## Task 4: Rust DB 初始化层

**已完成文件：**
- `src-tauri/src/db/mod.rs` — SqlitePool 初始化 + migration runner
- `src-tauri/src/lib.rs` — Tauri app 入口 + setup + 启动清理
- `src-tauri/src/main.rs` — 调用 `apicat_lib::run()`

**db/mod.rs 关键实现：**
```rust
pub struct AppDb(pub SqlitePool);  // 注册到 tauri::manage()

pub async fn init_db(app: &tauri::App) -> Result<SqlitePool, Box<dyn std::error::Error>> {
    let app_data_dir = app.path().app_data_dir()?;  // 平台标准 AppData 目录
    fs::create_dir_all(&app_data_dir)?;
    let db_url = format!("sqlite:{}?mode=rwc", db_path.display());
    let pool = SqlitePoolOptions::new().max_connections(5).connect(&db_url).await?;
    sqlx::query("PRAGMA journal_mode = WAL").execute(&pool).await?;  // WAL 模式
    sqlx::query("PRAGMA foreign_keys = ON").execute(&pool).await?;   // 开启外键
    run_migrations(&pool).await?;
    Ok(pool)
}
```

**migration runner** 将 SQL 编译时内嵌（`include_str!`），按分号分割逐条执行，跳过空行和注释。

**lib.rs 关键实现：**
```rust
.setup(|app| {
    let pool = tauri::async_runtime::block_on(init_db(app))?;  // 同步等待 DB 初始化
    app.manage(AppDb(pool.clone()));                             // 注册全局状态
    tauri::async_runtime::spawn(async move {                     // 异步清理旧测试用例
        cleanup_old_test_cases(&pool).await;
    });
    Ok(())
})
```

**启动清理 SQL（设计文档 4.2.2 两步逻辑）：**
```sql
DELETE FROM test_cases
WHERE starred = 0
  AND created_at < datetime('now', '-30 days')
  AND request_id IN (
    SELECT DISTINCT request_id FROM test_cases WHERE starred = 1
  );
```

## 已知约束 / 注意事项

### Windows 编译环境
`cargo check` / `cargo build` 必须在激活了 MSVC 环境变量的终端中运行，否则 `libsqlite3-sys` 编译时找不到 `cl.exe`。

**推荐方式：** 在 **VS 2022 Developer Command Prompt** 中执行所有 Rust 编译命令，或通过：
```bash
powershell -Command '$vsdev = "C:\Program Files\Microsoft Visual Studio\2022\Community\Common7\Tools\VsDevCmd.bat"; $psi = New-Object System.Diagnostics.ProcessStartInfo("cmd.exe"); $psi.Arguments = "/c `"$vsdev`" && cargo check 2>&1"; ...'
```

### DB 文件路径
- Windows：`%APPDATA%\com.apicat.app\apicat.db`
- macOS：`~/Library/Application Support/com.apicat.app/apicat.db`
- Linux：`~/.local/share/com.apicat.app/apicat.db`
